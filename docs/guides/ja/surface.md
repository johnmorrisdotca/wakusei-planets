`<wakusei-surface>` は、高さを実測してある場所の月面に視点を置きます。地面は実際の表面のモデルから描かれ、表示している時刻の本当の位置にある太陽に照らされ、地面自身の影が落ち、黒い空には実際の位置に、実際の満ち欠けの地球が浮かびます。いまあるのは1か所、アポロ17号の着陸地点（タウルス・リットロー）だけです。幅数キロの谷が、高さ2キロの山に挟まれています。

```ts no-run
import "@johnmorrisdotca/wakusei-planets/surface/element";

const view = document.createElement("wakusei-surface");
view.setAttribute("site", "apollo-17");
view.setAttribute("time", "1972-12-11T19:54Z"); // 着陸の瞬間：太陽は高度13度、影が長い
view.setAttribute("tiles", "https://johnmorrisdotca.github.io/wakusei-planets/tiles/");
document.body.append(view);
```

## 操作

ドラッグで向きを変えます。W・A・S・D（または矢印キー）で歩きます。速さは秒速1.4メートルで、目の高さは地面の起伏（クレーターを含む）に合わせて上下します。Q と E で左右を向き、+ と - でズームし、Ctrl を押しながらホイールを回すかピンチするとズームします。ズームは視野角（画面の上端から下端までの角度）で、8度から100度です。何も変わらないときは描きません。キーを押している間も、1秒に30フレームまでです。

属性は `site`、`time`（ISO の日時、1970年からのミリ秒、または `now`。省略すると着陸の瞬間）、`heading`（北から時計回りの度数）、`pitch`、`fov`、`tiles`（高さのタイルの置き場所）、`lang`、`quality`（`auto`（既定）、または `full`・`medium`・`fast`。「かかる負荷」を参照）です。試すためのものとして `shadows="off"`、`detail="off"`、`exposure` もあります。

## 地面の出どころ

高さのタイルは `scripts/make-moon-terrain.py` が、パブリックドメインの NASA のデータから作ります（NOTICE.md に、各ファイルの出どころと求められる表記を書いています）。使うのは、月周回機 LRO の狭角カメラによる5メートル間隔の高さモデルと、それより外側のためのレーザー高度計の全球地図です。前者はレーザー高度計の測定に結びつけてあるので、高さはおよそ1メートル、位置はおよそ10メートルの精度です。タイルは4階層（サンプル間隔5・20・80・480メートル）に分け、それぞれを256サンプル四方に切ります。高さは16ビットで、可逆圧縮（ロスレス）の WebP 画像として保存するので、元の高さとビット単位で一致します。高さの2バイトを2つの色成分に分けて入れているのは、ブラウザが16ビット画像をそのまま読めないためです。タイルはどのパッケージにもリポジトリにも入っていません。Pages のワークフローが作り、デモと並べて配信します。要素は既定でそこを見ます。

地平線は実測です。モデルは地点から29キロまで届き、そこから先は全球地図で、80キロ先の山も本当の位置にあります。月の丸みも引いてあります（地面は1キロで29センチ落ち、目の高さから見た平地の地平線は2.5キロです）。

地面の絵は、狭角カメラ自身のモザイク画像から、高さによる陰影を割り算で取り除いたものです。スクリプトがモザイクを照らしていた太陽（方位角と仰角）を、写っている地形の高さに合わせて求め、その陰影を取り除いて、地面そのものの明暗だけを残します。その絵を表示時刻の太陽でもう一度照らすので、二重に照らされることはありません。

## 光と影

太陽と地球は、このパッケージ自身の天体暦から求めます。`moonSky(lat, lon, time)` は、太陽と地球の方位と高度、見かけの大きさ、そして地球の明るい部分の割合を返します。地球の割合は月の満ち欠けの逆です（満月のとき、地球は新月の状態です）。地面の光は、月の砂が従う Lommel-Seeliger の法則で（太陽側で明るく、影の側ではまったく明るくなりません）、空気がないので霞はなく、空は黒です。

```ts
import { moonSky } from "@johnmorrisdotca/wakusei-planets/surface";

const sky = moonSky(20.1911, 30.7723, Date.UTC(1972, 11, 11, 19, 54));
console.log(`太陽は高度${sky.sun.altitude.toFixed(0)}度、地球は高度${sky.earth.altitude.toFixed(0)}度で${(100 * sky.earthIllumination).toFixed(0)}%が明るい`);
```

影はくっきりしていて、2つの部分からなります。実測した地面の影はあらかじめ焼き込んであります。スクリプトが高さを一度たどり、5・20・80メートルの各階層の各点について、18方向それぞれの地平線の高さを保存します（地平線マップ。階層と同じ大きさの画像で、この地点では4.4MBです）。シェーダーは太陽の方向の地平線を読んで太陽の高さと比べるので、山の影は1回の読み取りで済みます。光線を一定の歩幅で進める処理（レイマーチ）は、作ったものにだけ使います。太陽に向かって、高さと近くの作ったクレーターの上を、決まったステップ数だけ短く進めるので、足元ではクレーターの縁や石がくっきりした影を落とします。

## 実測ではなく、作ったもの

5メートルの格子より細かいものについてはデータがないので、作ります。作るのは、0.5メートルから20メートルの小さなクレーター（月面クレーターのサイズ頻度分布に従い、小さいものが多く大きいものは少なく、しかもほとんどが古いものです。新しいものは約25個に1個で、幅の5分の1の深さで縁が鋭く、4分の3は風化した浅いくぼみで、縁はやわらかく地面に溶け込みます。大きいものは半分に間引き、重なってもよいので、スタンプを押したような円が並ぶだけの地面にはなりません）、月の砂の細かいざらつき（法線に加えます）、岩（ほとんどが30センチ未満で、最大でも1.5メートル、丸みがあり、一部が埋まり、地面と同じ法則で光ります。日の当たる面は砂より少し明るく、新しい縁から離れるほど少なくなります）です。すべて場所を種にした乱数で作るので、同じ場所はいつも同じで、遠くでは薄れて消えるのでちらつきません。**作ったものであり、実測ではありません**。画面の地面の下にもそう書きます。`detail="off"` にすると実測の地面だけを見られます。目の高さも作ったクレーターに従うので、クレーターに踏み込めば下がります。

## かかる負荷

描くのは何かが変わったとき（視線の向き、一歩、時刻）だけで、止まっているときや見えていないときは何も描きません。キーを押している間も1秒に30フレームまでです。キャンバスは共有レンダラーのもので、ページ全体で WebGL コンテキストは1つ、600万ピクセル以内、1辺4096ピクセル以内です。

負荷はフラグメントシェーダーにかかり、`quality` で3段階に分かれます。`full` は作った細部を80メートルにわたり56ステップで進め、36メートルまでの作ったクレーターを読みます。`medium` は40メートルにわたり28ステップ、16メートルまでのクレーターです。`fast` は14メートルにわたり10ステップで、進める処理には作ったクレーターを含めません。およそ60メートルより遠い作ったクレーターは、面の法線だけを変え、影には関わりません。既定の `auto` は、最初の1枚と動いている間の絵を `fast` で描き、最後の変化の少し後（160ミリ秒後）に `full` で1枚描きます。1回の描画が120ミリ秒を超えたら1段階、250ミリ秒を超えたら2段階下げ、`stats.quality` で知らせます。グラフィックスカード（Apple M1 Ultra、ANGLE と Metal 経由）では、1280×720でも780×438でも、どの段階も約2ミリ秒で、カード自身のオーバーヘッドの時間なので、段階の違いは見分けられません。スマートフォンは測っていません。新しい機種では、100万ピクセルの `full` が15〜30ミリ秒ほど、安い機種では100ミリ秒以上かかる見込みで、そのために `auto` が段階を下げます。ソフトウェア描画（テストで使います）では、640×360の1枚が `full` で約30秒、`fast` で約5秒なので、テストは小さな画像と `fast` で行います。

地面は、着陸地点から外側へ向かって、同心円状に少しずつ取得します。最初の表示は4.2MBで、粗い階層をまるごと（サンプル間隔80メートル）、着陸地点を中心にした4×4タイル分の最も細かい階層（5メートル）、そのタイルの地面の絵、最も細かい地平線マップです。階層は最初の描画から全体がそろっていて、まだ取得していないタイルには、より粗い階層から作った値が入っています。そのため、残りが届くにつれて、地面は同じ場所のまま細かくなっていきます。順番は近い方からで、残りの5メートルと20メートルのタイル、他の地平線マップ、最後に80キロより遠い地形（いちばん遠い山にしか必要ありません）です。地点全体では12.9MBです（高さ7.0MB、地面の絵2.0MB、地平線マップ3.9MB）。`data-loading` 属性は、タイルがまだ届いている間は `more`、すべて届くと `done`、取得できないものがあると `failed` になります（最初の表示はそのまま使えます）。タイルの数は `stats.tiles` で分かります。

## 軌道から降りる

`<wakusei-space>` は、1回の呼び出しで、見ている人を軌道から地点まで降ろせます。`@johnmorrisdotca/wakusei-planets/surface/land` をインポートするだけで、`<wakusei-space>` 要素に `land(site)`、`leave()`、読み取り専用の `landed` と `standing` が加わります。インポートしないページには、月面に立つための表示のコードは含まれません。

```ts no-run
import "@johnmorrisdotca/wakusei-planets/space/element";
import "@johnmorrisdotca/wakusei-planets/surface/land";

const space = document.querySelector("wakusei-space")!;
space.addEventListener("wakusei-landed", (event) => console.log("着陸：", (event as CustomEvent).detail.site));
await space.land("apollo-17");
console.log(space.landed); // "apollo-17"
await space.leave();
```

カメラは、月にいなければ月へ行き、地点の上空へ回り込んで、月でいちばん近いズームまで寄ります。その間に、月面に立つ表示は待機状態で作られます。地面（最初の4.2MB）を取得するだけで、ページのレンダラーは使いません。ページにレンダラーは1つで、同時に持てる表示も1つなので、地面が届くと、軌道の表示は黒（月の空の黒）へ暗転し、その間に月面の表示がレンダラーを受け取って、地面が暗闇から浮かび上がります。動きを減らす設定の人には、切り替えだけです。始まるときに `wakusei-landing` を、立てたときに、`detail.site` に地点を入れた `wakusei-landed` を送ります。`leave()`（地面では Esc キーでも）は暗転し、レンダラーを軌道の表示に返し（宇宙の要素の `resume()`）、月全体まで上がって、暗闇から戻り、`wakusei-left` を送ります。`land` が返す Promise は `<wakusei-surface>` 要素で解決されます。その名前の地点がない、端末が3Dを描けない、地面のデータが時間内に届かない（`timeout`、既定は20秒）、または先に `leave` が呼ばれたときは、`land` は拒否され、軌道の表示は元のままです。同じ地点にもう一度 `land` すると、同じ表示が返ります。別の地点に `land` すると、最初のものは取り消されます。

## 宇宙の表示から

`<wakusei-space>` がすでにあるページ（時計はページが動かし、隣に別の表示がある場合）に必要なのは、次の5行だけです。

```ts no-run
import "@johnmorrisdotca/wakusei-planets/surface/land"; // 1回だけ。<wakusei-space> に land()、leave()、landed、standing が加わります
const space = document.querySelector("wakusei-space")!;
document.querySelector("#land")!.addEventListener("click", () => space.land("apollo-17").catch(() => alert("The ground did not come in."))); // 地面は、既定では Pages のタイルから取ります
document.querySelector("#leave")!.addEventListener("click", () => space.leave());
for (const type of ["wakusei-landed", "wakusei-left"]) space.addEventListener(type, () => console.log(type, space.landed));
```

- **時刻。** 地面には、`land` を呼んだ時点の軌道の表示の時刻（`space.time`）が1回だけ読み込まれるので、地面の上の太陽と地球は、上の表示で見えていたものと同じです。その後は時計に従いません。`land` は、降下とフェードのフレームのほかには、時計もタイマーもループも自分では動かさず、止まっているときは何もしません。`{ time: "landing" }` にすると、着陸の瞬間（太陽の高度13度）を表示します。ほかの時刻は ISO の日時かミリ秒で渡せます。その時刻に地点が夜なら、地面は暗くなります。
- **どこに置かれ、誰が大きさを決めるか。** `<wakusei-surface>` 要素は、宇宙の要素自身のシャドウルートの中に、全体を覆うように置かれます（`position: absolute; inset: 0`）。つまり宇宙の要素の枠がそのまま地面の枠で、ページが大きさを決めるのは宇宙の要素だけです。ページが置く必要のあるものはありません。`space.standing` で取り出せるので、`heading`、`pitch`、`time` を設定したり、イベントを聞いたりできます。
- **`leave` が取り除く方法。** `leave()` は、要素とその暗転用の幕をシャドウルートから取り除き、レンダラーを宇宙の表示に返します。ページには何も残らず、`landed` は `null` になります。
- **レンダラーは1つ。** 人が立っている間、ページのほかの動く表示（宇宙の表示の隣の地球）は、レンダラーが1つしかないため、静止画に戻ります。地面がその上にあるので、宇宙の表示の上のページ側の操作は、その間は隠しておくのがよいでしょう。
- **タイル。** 既定は `https://johnmorrisdotca.github.io/wakusei-planets/tiles/` で、その下の最初のファイルは `moon/apollo-17/manifest.json` です（別の場所は `{ tiles: "..." }` で指定します）。

## パッケージが出すもの

`WakuseiSurface`（要素。`surface/element` から）と `SURFACE_SITES` は立てる場所を、`moonSky` と `localFrame` は空を、`forward`、`viewProjection`、`clampLook`、`stepOver` はカメラを、`loadTerrain`、`tileAddress`、`groundAt`、`sampleLevel`、`decodeHeight` は高さを、`loadPlan` はファイルが届く順序を、`fillFromCoarser` はまだ届いていないタイルの中身を、`madeGround`、`craterIn`、`rocksAround`、`rockMesh` は作った細部を表します。細部の式はシェーダーと同じで、1か所（`src/surface/detail.ts`）に書き、テストで両者を揃えています。
