位置は NASA の JPL Horizons と比べて確かめています。Horizons は天体の位置の基準になるサービスです。`test/accuracy.test.ts` が、すべての惑星、月、衛星を、いくつかの日付で Horizons と比べます。下の限度より離れた天体が一つでもあると、テストは失敗します。表の数字は、それらの日付のうち一番悪かった値です。距離ではなく向きの違いで、惑星は太陽から見た角度、衛星は惑星から見た角度です。

絵として見るときは、衛星の軌道上の 1度は、画面で見る衛星の円盤の幅くらいです。1分角は、1ピクセルの何分の一かです。

## 惑星

水星から海王星は、VSOP87B の級数 (Bretagnon と Francou、IMCCE) から作っています。大事な項だけに短くして (全部で 35,080 項のうち 991 項)、地球時で計算します。地球時は、この理論が書かれている時刻系で、時計の UTC に閏秒と 32.184 秒を足したものです。VSOP87 にない冥王星は、Horizons に合わせた20区間の表 (1800年から2200年用) です。この年の範囲の外では、JPL の近似ケプラー要素で答えます。1800年から2050年の5つの日付で確かめました。

| 天体 | 一番悪かった値 | 限度 |
|---|---|---|
| 水星 | 2.3″ | 3.5″ |
| 金星 | 0.5″ | 1″ |
| 地球 | 1.5″ | 2.2″ |
| 火星 | 1.4″ | 2.2″ |
| 木星 | 1.9″ | 2.8″ |
| 土星 | 3.7″ | 5.6″ |
| 天王星 | 3.8″ | 5.8″ |
| 海王星 | 3.3″ | 5″ |
| 冥王星 | 0.05″ | 0.3″ |

1秒角は 1度の 3600分の1 です。一番ゆるいのは土星と天王星です。短くした級数は、大きさと引き換えに数秒角の誤差を認めているからです。VSOP87 にない冥王星は Horizons に合わせてあるので、一番近い値です。短くした級数は、1750年から2250年の間で有効で、それより外ではゆっくり悪くなります。1972年より前は、UTC から地球時への換算に、Espenak と Meeus (NASA) の式の ΔT を使い、1972年からは正確な値を使います。

## 準惑星

ケレス、オルクス、ハウメア、クワオアー、マケマケ、ゴンゴン、エリス、セドナは、冥王星と同じく Horizons に合わせた表です。チェビシェフの区間 (ケレスは1区間4年、動きの遅い天体は50〜200年) を、太陽系の重心から見た位置で作っています。遠い天体の動きは重心から見るとなめらかだからです。太陽から見ると、太陽自身が重心のまわりで12年かけて揺れる動き (木星の引力によるもので、約100万 km) が入ります。短い多項式ではこの揺れを追えないので、このパッケージは惑星の質量から揺れを計算して、あとで足し戻しています。表の年は、ケレスが1900年から2100年、ほかは1800年から2200年です。この範囲の外では、ある日の瞬間の軌道要素で答えます。2026年6月の前後数年は合います。フィットの格子の上にない、1900年から2099年の6つの日付で確かめました。

表は任意です。地球だけを描くページがこの分のサイズを払わなくてよいように、ウェブコンポーネントは表を読み込み、サーバーやスクリプトで `heliocentric` を呼ぶ場合は、必要な表を自分で import します。表がなければ、これまでの軌道要素で答えます。

```ts
import { heliocentric } from "@johnmorrisdotca/wakusei-planets";
import "@johnmorrisdotca/wakusei-planets/tables/dwarfs"; // オルクス、ハウメア、クワオアー、マケマケ、ゴンゴン、エリス、セドナ: gzip で約5 kB
import "@johnmorrisdotca/wakusei-planets/tables/ceres"; // ケレス、1900年から2100年: gzip で約14 kB

const [x, y, z] = heliocentric("ceres", Date.UTC(2000, 0, 1));
console.log(Math.hypot(x, y, z).toFixed(2));
```

`@johnmorrisdotca/wakusei-planets/tables` は両方を読み込みます。

## 月と衛星

月は月理論 ELP2000-82B (Chapront-Touzé と Chapront、IMCCE) を大きい540項に短くしたもので、惑星と同じく地球時で計算します。ほかの衛星の軌道は、1950年から2050年の Horizons の位置と速度に合わせています。軌道面を一つ決め、平均経度は一定の速さで進み、近点と昇交点は一定の速さで回る、という形です。一定の速さだけでは足りない衛星には、もう一つ項があります。軌道が縮んでいるフォボスには加速があり、たがいに引き合うミマスとテティスは、約70年かけて行ったり来たりします。1900年から2100年の7つの日付で確かめたので、合わせた期間の前後50年ずつが表に入っています。

## 何に使えるか

衛星は、軌道上で 1度か 2度の範囲で正しい場所に描かれます。絵、図、空の話には十分です。望遠鏡を向けたり飛行計画を立てたりする暦としては使えません。その場合は JPL Horizons そのものを使ってください。

## 自分で確かめる

`pnpm test` で精度のテストが動きます。`python3 -I scripts/fetch-horizons-reference.py` は Horizons の位置をもう一度取り直して `test/data/horizons.json` に書き、`python3 -I scripts/make-moon-data.py` は衛星を合わせ直して `src/data/orbits.ts` に書きます。どちらもネットワークが必要で、テストの中では動きません。

† Ceres・Eris の Python スコアは、元期付き軌道要素を固定 J2000 座標と解釈した値です。公開 API はこの2天体の座標系を明確に保証していないため、確定的な順位には使いません。日付黄道と解釈した場合の全期間最大値は ceres: 3066.112; eris: 4665.214 秒角です。両方の解釈を結果 JSON に保持しています。

Python パッケージの内部ユリウス日は、1800年のサンプルで2日、1900年1月のサンプルで1日早い値になります。入力日は修正していません。これは全期間表の大きな誤差の一因であり、通常期間の軌道精度だけを示す数値ではありません。Chiron は Python 側にありますが、共有できる参照・wakusei の実装がないため採点しません。

### 観測者から見た太陽・月：別の量

SunCalc の公開 API は視位置の地平座標を返すため、幾何学的な惑星表には混ぜません。既存の惑星・月の日付の和集合9日を使い、北緯35°・東経−105°・楕円体高0mで Horizons の視位置・大気差なしの方位角と高度を別途取得しました。各ライブラリーの大気差だけを数値的に取り除き、視差・光行差・光行時間・恒星時モデルの差は残して比較します。地平線より下も含み、天候や大気モデル自体の精度は測りません。

| 天体 | wakusei（秒角） | 上限 | astronomy-engine | solarsystem | suncalc |
|---|---:|---:|---:|---:|---:|
| sun (horizon) | 3.925 | 6.000 | 4.502 | — | 1140.685 |
| moon (horizon) | 4.839 | 8.000 | 77.952 | — | 13159.151 |

SunCalc 2.1.2 の TT−UT 多項式は約1900–2150年を対象とし、1800年は範囲外です。上の全期間値にはその外挿も含まれるため、通常期間の精度として宣伝してはいけません。1950–2050年の結果は最初の表にあります。この比較は方向だけです。出没時刻・食・位相の精度は証明しません。

### サイズ・ライセンス・再現

| パッケージ・版 | 測定したコード | gzip（バイト） | ライセンス |
|---|---|---:|---|
| wakusei 0.20.0 | メイン全出力＋/suncalc 全出力＋全ての任意テーブル | 65,653 | MIT |
| astronomy-engine 2.1.19 | ESM エントリーの全出力 | 43,971 | MIT |
| solarsystem 0.1.8 | Python 全モジュールのソース（下記参照） | 11,351 | MIT |
| suncalc 2.1.2 | ESM エントリーの全出力 | 3,893 | BSD-2-Clause |

JavaScript は esbuild 0.25.12 で全出力を ESM にバンドルして最小化し、gzip level 9 で圧縮します。wakusei の測定にはこの表で使う任意データと /suncalc を含み、メインの SVG・天体情報も含みます。Python はファイル名順の .py 全文を連結した gzip であり、JS バンドルとの単純な大小比較には使えません。どの値も言語ランタイム・インストール用メタデータ・画像を除きます。Python や Node の版によって gzip が少し変わることがあります。root の依存関係と src/ は変更していません。記録環境は Node v26.0.0（zlib 1.2.12）、Python 3.14.4（zlib 1.2.12）です。再現確認では最小化コードのバイト数とコードの指紋に一致を求めます。圧縮後のサイズ差は表示しますが、圧縮器の差を科学的な回帰とは判定しません。

同じ UTC インスタントを渡します。wakusei は理論を TT で実行し、Astronomy Engine は自身の Delta-T モデル、SunCalc は自身の TT−UT 多項式を使います。Python solarsystem は UT の日数をそのまま理論に使います。歴史的な Horizons の UT は近代的な UTC と同一ではなく、UT1・地球姿勢・将来の Delta-T の扱いも誤差に含まれます。入力時刻を調整して相手の結果を良くすることはしていません。同じ UTC 入力でも、内部の TT の仮定が一致するとは限りません。

リポジトリーのルートから次の順に実行します（Node 24以上、Python 3.12以上）。初回のインストールだけネットワークが必要です。通常の比較は保存した参照を使うためオフラインで実行できます。

~~~sh
pnpm install --frozen-lockfile
pnpm --dir scripts/compare install --frozen-lockfile --ignore-scripts
python3 -m venv scripts/compare/.venv
scripts/compare/.venv/bin/python -m pip install --require-hashes --only-binary=:all: --no-deps -r scripts/compare/requirements.txt
node scripts/compare/run.mjs
node scripts/compare/run.mjs --check
pnpm check
pnpm docs:check
~~~

Windows の仮想環境は Scripts/python.exe を使います。COMPARE_PYTHON で Python の実行ファイルを明示できます。run.mjs は results.json とこの英日セクションを生成します。--check は生成済みの値と文書が一致するか確認します。test/comparison.test.ts は第三者のインストールなしで、同じ参照日の wakusei の値が公開上限を超えないことを検査します。上限は自動で緩めません。

参照ベクトル・APIパラメーター・全ての日付ごとの誤差とワースト日付は scripts/compare/ にあります。新しい地平座標の参照を取得する場合だけ python3 -I scripts/compare/fetch-observer.py を実行します。浮動小数点の丸めによるゼロを避けるため、極小の角度にも acos を使いません。Horizons ベクトルは0.1km単位に丸められています。適合テーブルは同じ Horizons を元に作ったものなので、この表はその参照への一致度を示します。全期間の精度、未知の日付での精度、パッケージ全体の優劣はこの少数の点だけでは証明できません。
