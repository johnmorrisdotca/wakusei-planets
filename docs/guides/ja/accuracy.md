位置は NASA の JPL Horizons と比べて確かめています。Horizons は天体の位置の基準になるサービスです。3つのテストが、すべての惑星、月、衛星を Horizons と比べ、下の限度より離れた天体が一つでもあると失敗します。`test/accuracy.test.ts` は `test/data/horizons.json` のいくつかの基準日で、`test/accuracy-dense.test.ts` は1800年から2200年にちらばった60の日付 (`test/data/horizons-dense.json`、間隔は2437日で、惑星の公転周期に重ならないようにしています) で、`test/accuracy-fine.test.ts` はより細かい惑星の級数で確かめます。表の数字は、それらの日付のうち一番悪かった値です。距離ではなく向きの違いで、惑星は太陽から見た角度、衛星は惑星から見た角度です。

絵として見るときは、衛星の軌道上の 1度は、画面で見る衛星の円盤の幅くらいです。1分角は、1ピクセルの何分の一かです。

## 惑星

水星から海王星は、VSOP87B の級数 (Bretagnon と Francou、IMCCE) から作り、地球時で計算します。地球時は、この理論が書かれている時刻系で、時計の UTC に閏秒と 32.184 秒を足したものです。1972年より前は、UTC から地球時への換算に、Espenak と Meeus (NASA) の式の ΔT を使い、1972年からは正確な値を使います。VSOP87 にない冥王星は、Horizons に合わせた20区間の表 (1800年から2200年用) です。この年の範囲の外では、JPL の近似ケプラー要素で答えます。

級数の切り方は2つあり、ページは必要な精度の分だけサイズを払います。

- **ふつうの切り方**: 35,080 項のうち 995 項 (8つの惑星の全部で gzip 13.8 kB、これまでと同じ)。コードを変えなくても、誰でもこちらが使われます。
- **`tables/vsop`** (任意): 2,584 項 (gzip で約32 kB)。`tables` とは別に import すると、`heliocentric` がより細かい級数を使うようになります。

天体の絵と宇宙ビューは、どの倍率でもふつうの級数を使います。同じ60の日付で8つの惑星を比べ、見かけの向きと直径の最大の差を画面上の動きに換算すると、円盤の幅が4,096ピクセルでも0.20ピクセル未満です。宇宙ビューでは、注目している天体が画面の中心に来るように配置するため、その天体の太陽中心の位置が変わっても円盤の位置は変わりません。位置の計算にさらに精度が必要な場合は、細かい級数を import できます。

```ts
import { heliocentric } from "@johnmorrisdotca/wakusei-planets";
import "@johnmorrisdotca/wakusei-planets/tables/vsop"; // より細かい VSOP87B 級数: gzip で約32 kB

const [x, y, z] = heliocentric("saturn", Date.UTC(2026, 10, 7, 12));
console.log(Math.hypot(x, y, z).toFixed(1));
```

VSOP87 は JPL の DE200 に合わせてあるので、今の Horizons と比べると、木星と海王星の平均経度が時間に比例してずれています (海王星は2000年で 1.2秒角、そのあと1000年ごとに 13秒角)。`scripts/make-vsop-data.py` が、テストに使わない80の日付でこの直線を Horizons に合わせ、2つの級数から2つの項として取り除いています。取り除かないと、60の日付で海王星は 5.7秒角、木星は 3.1秒角ずれていました。

天王星の細かい級数では、経度に3つの補正項を加えています。一定のずれ、時間に比例するずれ、天王星の平均運動に合わせた周期項です。Horizons の768の日付で係数を求めました。1800年から2199年までの別の192の日付では、太陽中心での方向の最大誤差が2.03″から1.39″に下がりました。ふつうの級数では、時間に比例するずれだけを補正すると最大誤差が大きくなるため、発表されたままの係数を使います。

|---|---|---|---|---|---|---|---|

| 地球 | 8″ | 1.5″ | 3.1″ | 4″ | 0.5″ | 0.7″ | 14.1″ |
| 火星 | 58″ | 1.4″ | 4.8″ | 6″ | 0.7″ | 0.95″ | 11.4″ |
| 木星 | 309″ | 1.0″ | 2.8″ | 3.6″ | 0.5″ | 0.7″ | 13.7″ |
| 土星 | 545″ | 3.7″ | 4.4″ | 5.7″ | 0.8″ | 1.1″ | 19.8″ |

1秒角は 1度の 3600分の1 です。最初の列は、このパッケージの出発点 (JPL の近似要素を、5つの基準日で測った値) です。2列目と3列目は、今のコードを5日と60日で測った値です。信用できるのは60日のほうで、5日は回帰テスト用の格子なので、その間の日にはもっと悪くなる惑星があります。最後の列は同じ60日での [astronomy-engine](https://github.com/cosinekitty/astronomy) (MIT) です (`node scripts/compare/dense.mjs` で表示できます)。一番悪い日は、400年の両端に近いものが多くなります。経度の補正を加える前の、もとの VSOP87B では、35,080項をすべて使っても、Horizons との差は天王星で2.2秒角、海王星で3.7秒角でした。

級数は1750年から2250年の間で有効で、それより外ではゆっくり悪くなります。

## 準惑星

ケレス、オルクス、ハウメア、クワオアー、マケマケ、ゴンゴン、エリス、セドナは、冥王星と同じく Horizons に合わせた表です。チェビシェフの区間 (ケレスは1区間4年、動きの遅い天体は50〜200年) を、太陽系の重心から見た位置で作っています。遠い天体の動きは重心から見るとなめらかだからです。太陽から見ると、太陽自身が重心のまわりで12年かけて揺れる動き (木星の引力によるもので、約100万 km) が入ります。短い多項式ではこの揺れを追えないので、このパッケージは惑星の質量から揺れを計算して、あとで足し戻しています。表の年は、ケレスが1900年から2100年、ほかは1800年から2200年です。この範囲の外では、ある日の瞬間の軌道要素で答えます。2026年6月の前後数年は合います。フィットの格子の上にない、1900年から2099年の6つの日付で確かめました。

表は任意です。地球だけを描くページがこの分のサイズを払わなくてよいように、ウェブコンポーネントは表を読み込み、サーバーやスクリプトで `heliocentric` を呼ぶ場合は、必要な表を自分で import します。表がなければ、これまでの軌道要素で答えます。

```ts
import { heliocentric } from "@johnmorrisdotca/wakusei-planets";
import "@johnmorrisdotca/wakusei-planets/tables/dwarfs"; // オルクス、ハウメア、クワオアー、マケマケ、ゴンゴン、エリス、セドナ: gzip で約5 kB
import "@johnmorrisdotca/wakusei-planets/tables/ceres"; // ケレス、1900年から2100年: gzip で約14 kB

const [x, y, z] = heliocentric("ceres", Date.UTC(2000, 0, 1));
console.log(Math.hypot(x, y, z).toFixed(2));
```

`@johnmorrisdotca/wakusei-planets/tables` は両方を読み込みます。

| 天体 | 測った最悪値 | 守る上限 | 年 |
|---|---|---|---|
| ケレス | 0.16″ | 0.3″ | 1900〜2100 |
| オルクス | 0.04″ | 0.1″ | 1800〜2200 |
| ハウメア | 0.03″ | 0.1″ | 1800〜2200 |
| クワオアー | 0.08″ | 0.15″ | 1800〜2200 |
| マケマケ | 0.08″ | 0.15″ | 1800〜2200 |
| ゴンゴン | 0.01″ 未満 | 0.1″ | 1800〜2200 |
| エリス | 0.02″ | 0.1″ | 1800〜2200 |
| セドナ | 0.01″ 未満 | 0.1″ | 1800〜2200 |

これまで準惑星は、2026年の近くでしか合わない単純な楕円でした。ケレスは2000年で2°、1900年で9°ずれ、ほかも数分角ずれていました。

## 小天体

ベスタ、パラス、キロン、フォルス、ハレー彗星は、準惑星と同じやり方で Horizons に合わせた表です (太陽系の重心から見たチェビシェフの区間で、太陽の揺れは後から足します)。`scripts/make-minor-data.py` が作ります。区間の長さは同じではありません。それぞれ、合わせに使わず取っておいた見本の日付で1秒角以内にとどまる範囲で、できるだけ長くします (ベスタとパラスは2〜4年、キロンとフォルスは最長10年、ハレー彗星は太陽の近くで43日、遠くで16年)。区間の始まりは、表の `edges` に入っています。ハレー彗星は Horizons の記録 90000030、つまり1986年の回帰の解です。解を合わせた観測 (1835年から1994年) より先の彗星の軌道は予測で、惑星の引力は、このパッケージではなく解の中に入っています。

```ts
import { heliocentric } from "@johnmorrisdotca/wakusei-planets";
import "@johnmorrisdotca/wakusei-planets/tables/minor"; // ベスタ、パラス、キロン、フォルス、ハレー彗星: gzip で約48 kB

const [x, y, z] = heliocentric("halley", Date.UTC(1986, 1, 9, 12));
console.log(Math.hypot(x, y, z).toFixed(3)); // 近日点: 太陽から 0.587 au
```

`@johnmorrisdotca/wakusei-planets/tables` はほかの表といっしょにこれも読み込み、`<wakusei-space>` は自分で読み込みます (`<wakusei-body>` は、小天体に日時があるときに取りに行きます)。Horizons との比較は12の日付で、日付ごとに1回ずつ問い合わせています (Horizons は、日付のリストをまとめて問い合わせると、リストの最初の日付の地球時と世界時の差を、すべての時刻に使います。1835年から始まるリストだと2026年が1分ずれ、ハレー彗星の近日点では6秒角のずれになります)。値は太陽から見たものです。

| 天体 | 測った最悪値 | 守る上限 | 年 |
|---|---|---|---|
| ベスタ | 0.18″ | 1″ | 1900〜2100 |
| パラス | 0.13″ | 1″ | 1900〜2100 |
| キロン | 0.21″ | 1″ | 1800〜2200 |
| フォルス | 0.10″ | 1″ | 1800〜2200 |
| ハレー彗星 | 0.53″ | 1″ | 1800〜2200 |

この年の外では、どれも Horizons の接触軌道要素 (1つの時点のもの) による単純な楕円です。惑星の引力で本当の軌道からずれていき、ベスタは1835年で2.5°、2134年で1.9°、パラスは1835年で8°ずれ、要素が1968年のハレー彗星は、表がないと2026年に31°ずれます。どの理論が答えたかは `heliocentricModel` でわかります。

## 月と衛星

月には、月理論 ELP2000-82B (Chapront-Touzé と Chapront、IMCCE) の大きい540項を使い、惑星と同じく地球時で計算します。Horizons の768の日付で平均経度の最初の3つの係数を合わせ直しました。1800年から2199年までの別の192の日付で、方向の最大誤差が5.31″から0.90″に下がりました。テストでは、これらの日付で1.1″以内に収まることを確かめます。もとの37,872項をすべて使っても、同じ60の日付で最大誤差が変わるのは0.13″だけなので、この合わせ直しでも540項のままにしています。

火星、木星、土星には、発表された軌道モデルを使う任意の入口があります。`tables` は3つとも読み込みます。コードを分割した場合、ウェブコンポーネントはその惑星の衛星を描くときだけ、対応するモデルを読み込みます。

- **フォボスとダイモス**は [Jacobson の平均軌道要素](https://doi.org/10.1088/0004-6256/139/2/668) と平均経度の補正を使います (`tables/mars-moons`)。1960年から2040年まではこのモデルで位置を求めます。論文が対象とする1950年から2050年の外では、Horizons に合わせた軌道を使います。その範囲の最初と最後の10年間は、位置と速度がなめらかにつながるように、両方から求めた位置を徐々に切り替えます。
- **イオ、エウロパ、ガニメデ、カリスト**: L1.2 (Lainey、Duriez、Vienne 2006、IMCCE)。140項に短くし、ゆっくりした揺れにはチェビシェフ多項式を使います (`tables/galilean`、gzip で約5 kB)。1130年から2760年まで有効です。
- **ミマス、エンケラドス、テティス、ディオネ、レア、タイタン、ハイペリオン、イアペトゥス**には TASS1.7 を使います (`tables/saturn-moons`、gzip で約11 kB)。たがいに影響し合う7つの衛星には Vienne と Duriez (1995、IMCCE) の316項を使い、ハイペリオンには専用の級数から230項を使います。

```ts
import { system } from "@johnmorrisdotca/wakusei-planets";
import "@johnmorrisdotca/wakusei-planets/tables/saturn-moons"; // TASS1.7 による8つの軌道、gzip で約11 kB

const titan = system("saturn", Date.UTC(2026, 10, 7, 12)).moons.find((moon) => moon.id === "titan");
console.log(Math.round(titan?.distance ?? 0));
```

そのほかの衛星の軌道と、上の表を import する前の衛星の軌道は、1800年から2199年の Horizons の位置と速度に合わせています。軌道面を一つ決め、平均経度は一定の速さで進み、近点と昇交点は一定の速さで回る、という形です。一定の速さだけでは足りない衛星には、もう一つ項があります。軌道が縮んでいるフォボスには加速があり、たがいに引き合うミマスとテティスは、約70年かけて行ったり来たりします。以前は1950年から2050年だけに合わせていたので、フォボスは1800年に4°、アリエルは2194年に1.4°ずれていましたが、今は 0.41° と 0.22° です。天王星と海王星の衛星には、Horizons に合わせた軌道を使います。

Jacobson が対象とした100年間の別の192の日付で、火星の中心から見た方向の最大誤差は、フォボスで0.22°から0.14°へ、ダイモスで0.38°から0.17°へ小さくなりました。切り替え中も含む値です。Jacobson のモデルだけを使う154の日付での最大誤差は、フォボスが0.042°、ダイモスが0.091°でした。下の60の日付による比較には、論文の対象期間より前と後の日付も含まれます。

60の日付では、ガリレオ衛星は astronomy-engine より 6〜11倍近くなります (`node scripts/compare/dense.mjs`: イオ 411″ 対 2,626″、エウロパ 132″ 対 1,403″、ガニメデ 92″ 対 814″、カリスト 52″ 対 379″)。月は 2.47″ 対 207″ です。

- **ハイペリオン**は、タイタンと4対3の軌道共鳴にあります。1800年から2199年までの Horizons の別の192の日付で比べると、土星の中心から見た方向の最大誤差は、合わせた軌道の14.40°から TASS1.7 の0.82°に下がりました。テストでは、読み込み後の理論の誤差が、これらの日付で1°以内に収まることを確かめます。Orbiter の全項を使った計算との差は、同じ日付で最大0.015°です。任意の表を読み込むまでは合わせた軌道を使います。
- **ミマス、エンケラドス、ミランダ、ネレイド**は軌道上の位相を補正します。1800年から2199年までの Horizons の768の日付を使い、長期的なずれ（ドリフト）といくつかの周期項を求めました。別の192の日付で測った最大誤差は、順に 0.395°、0.036°、0.306°、2.08° です。ネレイドは離心率が 0.75 と大きく、近点付近ではわずかな時刻のずれも大きな角度差になります。
- **ニクスとヒドラ**は冥王星系の重心を回ります。衛星系での位置は、系の質量に占めるカロンの割合と、その時点での冥王星から見たカロンの位置を使って、冥王星の中心を原点にして求めます。別の192の日付で、以前の軌道と今回の軌道を同じ冥王星中心の Horizons の位置と比べたところ、最大誤差はニクスで 2.01° から 0.363°、ヒドラで 1.68° から 0.686° に下がりました。表の「以前」の列は、重心を原点にした以前の測定です。
- **ステュクスとケルベロス**は、衛星カタログの平均軌道要素です（JPL の Planetary Satellite Mean Elements、暦 PLU060、元期 2026-01-01）。この Horizons との照合には入っていません。距離がこの二つを名乗るときは 5° まで許します。
- 冥王星以外の準惑星の衛星 (エリス、ハウメア、マケマケ、オルクス、クワオアなど) は、`src/data/dwarf.ts` に書いた論文から作っていて、この確認には入っていません。

### あとから形といっしょに加えた衛星

さらに15個の衛星を、探査機が測った形でくわしく描きます。木星のアマルテアとテーベ、土星のパン、ダフニス、アトラス、プロメテウス、パンドラ、エピメテウス、ヤヌス、テレスト、カリプソ、ヘレネ、ハイペリオン、フェーベ、海王星のラリッサです。軌道は同じやり方で合わせています。Horizons がその衛星の暦を持っている年について、Horizons の位置に一度だけ合わせます (表のとおり。ヤヌス、エピメテウス、アトラス、プロメテウス、パンドラ、パンは1949-12-27から2050-01-06まで、ダフニスは1990-06-15から2018-01-14までしかありません)。それより外の年は、直線をそのままのばしているだけで、確かめていません。平均軌道で追いきれない衛星は、一番大きなずれが大きく、制限がそれを示しています。

- **ヤヌスとエピメテウス**は、4年ごとに軌道を入れかえます (一方が外へ動くと、もう一方が内へ動きます)。どちらも一定の速さでは回りません。

- **ヘレネ**は、ディオネの先を行くトロヤ点のまわりを数十度の幅でゆれ (秤動し)、**テレストとカリプソ**は、テティスの同じ点のまわりを約10°の幅でゆれます。
- **パン、ダフニス、アマルテア、テーベ、フェーベ、ラリッサ**は近く、1〜2° 以内です。

## 何に使えるか

惑星は数秒角の範囲で、衛星は軌道上で 1度か 2度の範囲 (木星の4つ、土星のタイタンとイアペトゥスは数百分の1度) で正しい場所に描かれます。絵、図、空の話には十分です。望遠鏡を向けたり飛行計画を立てたりする暦としては使えません。その場合は JPL Horizons そのものを使ってください。

## 自分で確かめる

`pnpm test` で精度のテストが動きます。`python3 -I scripts/fetch-horizons-reference.py` と `python3 -I scripts/fetch-horizons-dense.py` は Horizons の位置をもう一度取り直して `test/data/horizons.json` と `test/data/horizons-dense.json` に書きます。`python3 -I scripts/make-vsop-data.py` (と `fine`)、`make-lunar-data.py`、`make-galilean-data.py`、`make-tass17-data.py`、`make-moon-data.py` は、`src/data` の級数と軌道を書きます。どれもネットワークが必要で、テストの中では動きません。

### 観測者から見た太陽・月：別の量

SunCalc の公開 API は視位置の地平座標を返すため、幾何学的な惑星表には混ぜません。既存の惑星・月の日付の和集合9日を使い、北緯35°・東経−105°・楕円体高0mで Horizons の視位置・大気差なしの方位角と高度を別途取得しました。各ライブラリーの大気差だけを数値的に取り除き、視差・光行差・光行時間・恒星時モデルの差は残して比較します。地平線より下も含み、天候や大気モデル自体の精度は測りません。

| sun (horizon) | 3.925 | 6.000 | 4.502 | — | 1140.685 |

### サイズ・ライセンス・再現

| パッケージ・版 | 測定したコード | gzip（バイト） | ライセンス |
|---|---|---:|---|
| wakusei 0.78.0 | メイン全出力＋/suncalc 全出力＋全ての任意テーブル（より細かい惑星級数 tables/vsop を除く） | 145,089 | MIT |
| astronomy-engine 2.1.19 | ESM エントリーの全出力 | 43,912 | MIT |
| solarsystem 0.1.8 | Python 全モジュールのソース（下記参照） | 11,351 | MIT |
| suncalc 2.1.2 | ESM エントリーの全出力 | 3,908 | BSD-2-Clause |

JavaScript は esbuild 0.25.12 で全出力を ESM にバンドルして最小化し、gzip level 9 で圧縮します。wakusei の測定にはこの表で使う任意データと /suncalc を含み、メインの SVG・天体情報も含みます。Python はファイル名順の .py 全文を連結した gzip であり、JS バンドルとの単純な大小比較には使えません。どの値も言語ランタイム・インストール用メタデータ・画像を除きます。Python や Node の版によって gzip が少し変わることがあります。root の依存関係と src/ は変更していません。記録環境は Node v24.22.1（zlib 1.3.2.1-motley-285e94b）、Python 3.14.4（zlib 1.2.12）です。再現確認では最小化コードのバイト数とコードの指紋に一致を求めます。圧縮後のサイズ差は表示しますが、圧縮器の差を科学的な回帰とは判定しません。

同じ UTC インスタントを渡します。wakusei は理論を TT で実行し、Astronomy Engine は自身の Delta-T モデル、SunCalc は自身の TT−UT 多項式を使います。Python solarsystem は UT の日数をそのまま理論に使います。歴史的な Horizons の UT は近代的な UTC と同一ではなく、UT1・地球姿勢・将来の Delta-T の扱いも誤差に含まれます。入力時刻を調整して相手の結果を良くすることはしていません。同じ UTC 入力でも、内部の TT の仮定が一致するとは限りません。

リポジトリーのルートから次の順に実行します（Node 24以上、Python 3.12以上）。初回のインストールだけネットワークが必要です。通常の比較は保存した参照を使うためオフラインで実行できます。

~~~sh
pnpm install --frozen-lockfile
pnpm --dir scripts/compare install --frozen-lockfile --ignore-scripts
python3 -m venv scripts/compare/.venv
scripts/compare/.venv/bin/python -m pip install --require-hashes --only-binary=:all: --no-deps -r scripts/compare/requirements.txt
node scripts/compare/run.mjs
node scripts/compare/run.mjs --check
pnpm check
pnpm docs:check
~~~

Windows の仮想環境は Scripts/python.exe を使います。COMPARE_PYTHON で Python の実行ファイルを明示できます。run.mjs は results.json とこの英日セクションを生成します。--check は生成済みの値と文書が一致するか確認します。test/comparison.test.ts は第三者のインストールなしで、同じ参照日の wakusei の値が公開上限を超えないことを検査します。上限は自動で緩めません。

参照ベクトル・APIパラメーター・全ての日付ごとの誤差とワースト日付は scripts/compare/ にあります。新しい地平座標の参照を取得する場合だけ python3 -I scripts/compare/fetch-observer.py を実行します。浮動小数点の丸めによるゼロを避けるため、極小の角度にも acos を使いません。Horizons ベクトルは0.1km単位に丸められています。適合テーブルは同じ Horizons を元に作ったものなので、この表はその参照への一致度を示します。全期間の精度、未知の日付での精度、パッケージ全体の優劣はこの少数の点だけでは証明できません。
