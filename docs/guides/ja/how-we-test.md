以下のチェックごとに、何を何と比べて測るかを書いています。失敗したチェックは変更を止めます。参考扱いのチェックはありません。

## 単体テストとカバレッジの下限

`pnpm test` は Node 標準のテストランナーで `test/*.test.ts` を実行します。計算、データ表、純粋なエントリーポイント、要素のロジックが対象で、ブラウザは使いません。`pnpm test:coverage` は同じテストを Node 組み込みのカバレッジ付きで `src/` に対して実行し、どれかの数値が下限を下回ると失敗します。`pnpm check` がこれを実行し、CI は `pnpm check` を実行します。

下限は 2026-11-17 の実測値（行 96.28%、分岐 93.48%、関数 95.86%）のすぐ下に置いています。**行 96、分岐 93、関数 95** です。値は `package.json` の `test:coverage` スクリプトにあります。下限は上げるだけです。ある変更で数値が 1 ポイント以上上がったら、同じ変更で下限も上げます。変更を通すために下げることはしません。

## ブラウザ：デモとドキュメントサイト

`pnpm test:demo` はデモとドキュメントサイトをビルドし、実際のブラウザで Playwright のテストを実行します。Chromium と WebKit、デスクトップ幅とスマートフォン幅の両方です。人が見るもの、押すものを確かめます。絵が描かれること、操作が働くこと、ページ同士のリンクが通ることです。

## フリーズとソーク

`pnpm test:freeze` は WebGL やキャンバスで描くページを開き、止まるべきときに止まることを確かめます。静止中は描画せず、見えないときや隠れたタブでも描画せず、キャンバスやグラフィックスオブジェクトは上限の内に収まります。`pnpm test:soak` はページを 1 分間動かし（`SOAK_MINUTES` で変更できます）、メモリやオブジェクトが増え続けないことを確かめます。

## Horizons との精度比較

位置は NASA の JPL Horizons と比べています。`test/` のテストは、すべての惑星、月、衛星、彗星、小惑星、接近について、Horizons の答えからの距離が決めた値以内であることを確かめ、超えれば失敗します。数値は[精度](accuracy.md)にあります。

## 使い方

`pnpm test:usage` は、README とガイドが示す使い方（script タグ、バンドラ、React、Vue、Svelte、Angular、iframe）をそれぞれビルドし、ブラウザで開きます。動かなくなった使い方はここで失敗します。

## docs の例

`pnpm docs:check` は、ドキュメントと TSDoc コメントにあるすべての TypeScript の例をビルド済みパッケージに対して型検査し、Node で実行します。壊れたリンクやフロントマターも失敗にします。

## サイズの予算

`pnpm size:budget` は、公開している各エントリーポイントを利用者のバンドラと同じようにバンドルして最小化し、gzip 圧縮して、そのバイト数を `scripts/size-baseline.json` と比べます。基準より **5%** を超え、かつ 256 バイトを超えて大きくなったとき、基準がないとき、基準にあるエントリーが無くなったときに失敗します。`pnpm check` がビルドの後に実行します。

意図して大きくするときは、`pnpm size:budget:update` を実行し、新しい `scripts/size-baseline.json` を、大きくした変更と同じコミットに入れ、理由を変更履歴に書きます。
